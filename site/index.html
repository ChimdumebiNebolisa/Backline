The lifecycle

One shared state. Two revisions. No silent restore.

Every phase is sequential so the evidence has a stable order and a clear owner.

  1. 01

    Baseline

    Start base components and establish base-only behavior.

    base
  2. 02

    Transition

    Run candidate-defined transition hooks while the original base stays alive.

    base remains
  3. 03

    Three controls

    Check base, candidate, then the same original base again before attribution.

    control × 3
  4. 04

    Coexistence

    Exercise base-to-candidate, candidate-to-base, and alternating scenarios.

    base + candidate
  5. 05

    Candidate cutover

    Stop base, run optional candidate-only hooks, then representative mutating traffic.

    candidate only
  6. 06

    Rollback

    Stop candidate, optionally prepare state, and start fresh base containers.

    fresh base

Attribution controls

Bracket the mixed stage before blaming it.

A failed transition or broken candidate is not automatically a compatibility failure. Backline checks both revisions around coexistence so precondition failures become inconclusive instead of misleading.

Rollback claim

Raw and prepared are different answers.

Backline always states which claim it tested. Candidate stops before either mode, and fresh base containers start without restoring shared services or volumes.

RAW

Untouched handoff

Fresh base checks state directly after candidate cutover and traffic.

PREPARED

Declared procedure

Configured rollback hooks prepare state before fresh base checks it.

Safety boundary

Trusted code, isolated resources.

Backline reduces accidental machine and Compose risk. It does not sandbox hostile project code.

Committed candidate config

Configuration and paths come from the resolved candidate Git object, not uncommitted files.

Loopback-only ports

Addressable components use Docker-assigned random ports bound to 127.0.0.1.

Owned cleanup

Run labels and exact registries prevent broad or cross-run resource deletion.

Not a sandbox

Backline is not a sandbox. Hooks, workloads, and Dockerfiles are trusted code and can make external calls.
